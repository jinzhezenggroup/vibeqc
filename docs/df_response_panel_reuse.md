# Reuse raw response panels across Coulomb and exchange

Executed 96/192-AO generated-response traces attribute about 492/2464 ms to
raw three-center generation out of 634/3828 ms of response time. The AO matrix
products account for only about 2/9 ms. The response's existing scratch already
holds raw and weight panels, but it previously regenerated raw values for the
charge pass, raw panel fill and exchange contraction separately.

Charge construction now fills the first reserved raw panel. The response
weight loop consumes that panel without refilling it, and exchange uses the
current panel's own raw slice whenever its auxiliary index is present. Other
slices retain bounded regeneration. All consumers enqueue work on the same
stream before the panel is overwritten; no allocation, stream, synchronization,
tensor layout or accumulation order changes.

For A auxiliary functions and a panel width B, G=ceil(A/B) blocks now generate
`(G+1)*A-B` raw AO slices, compared with `(G+2)*A` previously. When B=A, the
response generates the full raw tensor once instead of three times, using the
already resolved scratch allocation. A constrained panel still reports its
remaining repeated production. `raw_value_cache_hits` and
`raw_value_reuse_bytes` count avoided slice reads; generated byte/resource
counters continue to count actual callback execution.

The cache retains exact raw A values. Reconstructing them from a truncated
forward transformed tensor could discard metric directions needed by the
spectral Frechet derivative. The metric eigensystem, cutoff, discarded-space
response and generated center derivatives therefore retain their existing
equations. Native tests cover full and partial panels, RHF/UHF, rank-deficient
metrics, exact generated-slice counts and the existing host/device caps.
