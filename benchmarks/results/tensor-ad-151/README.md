# TensorIR generated JVP/VJP CUDA evidence (#151 slices B/C)

This directory records the real-device numerical and resource evidence for
demand-driven TensorIR JVP/VJP programs generated by
`tools/tensor_ad_examples.py`. The fixture is a fixed, unconverged CC-like
scalar energy fragment with differentiable `t`, `f`, and `g` parameters. It is
not a complete CCSD/MP2 method or solver.

## Environment

- Host: `node5` (n5), NVIDIA GeForce RTX 5090 through Slurm
  (`--partition=main --gres=gpu:5090:1`)
- CUDA compiler: CUDA 12.9.1, target `sm_120`
- Python 3.12.12, NumPy 2.3.4
- Source revision: `4707632ca91c` (`dirty=False`)

## Reproduction

```bash
# CPU native build used by the Python suite
cmake -S . -B build -G Ninja -DVIBEQC_ENABLE_CUDA=OFF \
  -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel

# Full CPU suite
VIBEQC_LIBRARY=$PWD/build/libvibeqc.so \
PYTHONPATH=$PWD/python:$PWD \
python -m pytest tests/python -q

# Real-device evidence (must run inside the allocated Slurm job)
srun --partition=main --gres=gpu:5090:1 --nodes=1 --ntasks=1 \
  --time=00:15:00 bash -lc '
    export VIBEQC_LIBRARY=$PWD/build/libvibeqc.so
    export PYTHONPATH=$PWD/python:$PWD
    python tools/tensor_ad_examples.py --mode numerical \
      --nvcc /group/software/cuda-12.9.1/bin/nvcc \
      --architecture sm_120 \
      --output build/tensor-ad-evidence-final \
      --cache build/tensor-ad-cuda-cache
  '
```

## Results

The shared `vibeqc.validation` schema gates each generated program against the
independent CPU interpreter with `atol=1e-11`, `rtol=1e-10`. Directional
finite differences use steps `1e-3`, `1e-4`, and `1e-5`; the packed dot
identity uses `rtol=1e-10`.

| Program | Numerical | Dot relative error | Recomputed nodes | Allocated bytes | Observed device delta | Planned peak bytes |
| --- | --- | --- | --- | --- | --- | --- |
| JVP | pass | `3.9675282341427827e-16` | 0 | 16,790,528 | 18,874,368 | 105,010,952 |
| VJP | pass | `3.9675282341427827e-16` | 5 | 14,692,096 | 16,777,216 | 105,009,672 |

Both plans use `views=True`, `fuse=True`, `recompute=True`,
`direct_gemm=False`, and `tile_m=tile_n=tile_k=32`. The JVP plan has 19 steps
and the VJP plan has 20 steps. Planned peak bytes include the checked 96 MiB
cuBLAS provider-retained allowance; observed device deltas are independent
measurements and are not a process-RSS or total-free-VRAM promise.

## Files

- `evidence.json`: the two shared-schema GPU numerical records.
- `jvp.evidence.json`, `vjp.evidence.json`: per-program evidence.
- `jvp.plan.json`, `vjp.plan.json`: replayable storage/lifetime plans.
- `primal.equation.json`, `jvp.equation.json`, `vjp.equation.json`:
  replayable TensorIR programs.

## Scope

The generated programs are matrix-free reverse evaluations of one fixed
fragment. They do not materialize a dense CC Jacobian and do not grow with a
solver iteration count. No production promotion or performance pass is
claimed; `performance` is explicitly `not-run`.
