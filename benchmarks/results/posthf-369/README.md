# Issue #369 generated-DF device-resident evidence

Date: 2026-09-20
Device: NVIDIA GeForce RTX 5090
CUDA compiler: 12.9.86 (`sm_120`)

This archive qualifies the generated density-fitting producer/consumer handoff
added for #369. The production CUDA response backend reuses the already prepared
`CudaDFSource`; the explicit matrix oracle uses a separate source through the
retained host-staged compatibility path.

The two endpoints intentionally are not presented as a speedup comparison: the
host oracle builds an explicit response matrix while the device path performs
matrix-free J/K actions and iterative solves. The evidence instead verifies the
required end-to-end data-movement distinction and numerical equivalence. Current
restricted RI-MP2 remains a CPU `DFProvider` consumer, so these results do not
claim a native CUDA RI-MP2 implementation.

| H2 | 2 / 2 | 384 | 147 | 0.116249 | 64 | 0 / 0 | 0.120280 | 1.22e-15 |
| LiH | 6 / 6 | 20,736 | 4,506 | 3.859913 | 1,728 | 0 / 0 | 0.136989 | 1.59e-13 |
| H2O | 7 / 7 | 49,392 | 11,673 | 8.614536 | 2,744 | 0 / 0 | 0.154063 | 6.53e-14 |

The host D2H counter is exactly the raw generated value traffic delivered to
Python for this oracle workload. The device path counts density input and final
J/K result transfers separately; those transfers are not hidden under the raw
DF counters. All device records report `source_reused=true` and provenance
`device-resident-generated-df-reused`.

Numerical checks from the same runs:

| case | dot-identity error | finite-rotation error |
| --- | ---: | ---: |
| H2 | 5.55e-17 | 2.80e-11 |
| LiH | 0 | 9.09e-11 |
| H2O | 2.41e-16 | 1.14e-09 |

All sequential, blocked and recycled response solves converged. The JSON files
retain per-strategy residuals, complete endpoint timing, generated tile counts,
source timings, host transformation work and explicit transfer counters.

## Interpretation

The old compatibility path remains available and auditable: provenance identifies
it as `host-staged-compatibility`, reports nonzero D2H traffic and host transform
work, and is ineligible by itself for CUDA performance claims. The production
CUDA response path consumes the same native generated-integral source directly,
so generated DF values are never unconditionally downloaded and re-uploaded
before the GPU contraction. No alternate integral evaluator is introduced.
