# Decision: prune IntegralIR outputs before generated HF value lowering

Status: implemented
Date: 2026-09-20

## Problem

Issue #673 Slice A established effect-aware liveness, but a resolved IntegralIR
could still carry force derivative intent into a Fock subplan when the enclosing
production selection requested both Fock and force. The backend already used
value-only arithmetic in several places, yet the mathematical subplan remained
over-specified and could expose derivative-sized state to scheduling.

## Decision

Add specialize_integral_ir as the backend-neutral Slice B boundary for
compile-time requested direct-HF outputs. It preserves exact retained
contraction records, removes unrequested outputs, drops derivative intent when
no retained output needs it, and folds a Rys root count to the value-only order
when derivative demand disappears.

Generated CUDA Fock subplans now pass through that specialization boundary.
Mixed FOCK+FORCE plans therefore schedule the Fock consumer from a FOCK-only
IntegralIR rather than reusing the derivative-bearing force request.

The fixed-root component-lane Fock worker is a deliberate exception at the
lowering-support layer, not at the requested-output layer. It reuses Rys tables
and recurrence state generated by the derivative-bearing force program. The
pruned Fock plan remains derivative-free, while that original IntegralIR is
passed separately as an explicit live support dependency. Removing FORCE from
the requested outputs therefore does not incorrectly delete shared computation
that the selected value lowering still consumes. This support is inherited only
when the Fock lowering itself inherits or derives its schedule from that force
plan. An explicitly independent Fock schedule remains independent and does not
silently acquire a Rys support dependency.

Only proven request facts are consumed. Geometry, density, convergence state,
runtime values, benchmark names, and endpoint measurements never participate.

## Compatibility boundary

A Fock-only production translation unit still contains the historical
compatibility force symbol used directly by the bounded spd force path. Slice B
does not remove or change that external/runtime ABI. Removing its signature,
launch packing, and provider preparation belongs to #673 Slice C after the
bounded caller is separated from that compatibility contract.

This distinction is intentional: the requested Fock executable subgraph is now
value-only, while an externally reachable compatibility entry point remains a
root rather than being incorrectly classified as dead code.

## Validation intent

Tests cover deterministic direct-output pruning, preservation of exact retained
contractions, derivative/Rys constant specialization, fail-closed invalid
demands, and a generated HF Fock subplan whose Coulomb state space is strictly
smaller than the enclosing mixed force plan.
