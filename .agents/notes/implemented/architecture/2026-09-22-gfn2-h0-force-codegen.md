# GFN2 CUDA H0-force compiler cutover

The production H0-force CUDA path now keeps only runtime ownership: ragged
shell/AO traversal, validation, reductions, atomics, stream ordering and
failure-atomic publication.

Compiler-owned TensorIR supplies the stationary Pulay seed, Cartesian separation
norm and its reverse pullback, the same-atom and separated-atom H0 pair factors,
reverse-mode CN/radial adjoints, and the per-AO overlap/block-weight contraction. The separated-atom radial response is generated by reverse AD of
the same primal factor, so the CUDA consumer no longer maintains the reduced
distance polynomial derivative by hand.

The runtime still owns coordinate-difference loading and the coincident-atom
threshold/error policy, but the norm and Cartesian response arithmetic are
generated so no H0-force chain-rule formula remains in the CUDA consumer.

This is independent of the open GFN2 Hamiltonian/S-D-Q CUDA cutover and does
not consume or modify that PR's generated family.
