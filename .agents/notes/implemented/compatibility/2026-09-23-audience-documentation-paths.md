# Decision: audience guides preserve machine-consumed documentation paths

Status: implemented
Date: 2026-09-23

## Decision

Organize reader-facing guides under audience directories, but retain generated
Libxc import and coverage reports at their registered root paths, alongside the
public method table and existing machine-readable artifacts. The bulk import
report is a hashed `upstream/manifest.json` output and an importer destination;
the Maple coverage report is independently regenerated by its snapshot test.
Moving their readers alone would leave registry or generator contracts stale.

Keep `docs/xc_expressions.md` as a forwarding page to the developer guide. That
path is embedded in serialized functional-domain metadata. Updating the
scientific descriptor just to repair a documentation URL would change source
and equation identities for an editorial operation.

Current CUDA ownership and evidence-retention ledgers follow the relocated
guides. Historical numerical/provenance JSON retains its original contents.
Links in Agent Notes and benchmark READMEs follow current guides without
rewriting the historical rationale or measurement records. The density-source
publication also hashes its README; preserve that file byte-for-byte and keep
`docs/density_sources.md` as its forwarding target.

## Evidence

The initial migration failed three document-reading tests and source-registry
validation. Preserving generated reports and updating MP2 document consumers
restores all 30 selected documentation, coverage and registry tests. A local
Markdown target audit repaired 69 migration-induced links, including extra
parent traversals in cross-audience references and inbound historical links.
The unrelated pre-existing missing benchmark JSON link remains outside this
migration's acceptance claim. Full repository checks also validate the current
ownership and retention ledger paths.

## Revisit when

Relocate a generated report only with its producers, consumers and registry
updated together. Retire the XC forwarding path only after the serialized
metadata contract no longer refers to it.
